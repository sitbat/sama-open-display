# `CC` 局部更新首次真机结果

> 历史失败案例；其中的“尚未真机写入”“未暴露入口”只描述首次测试时的状态。现行差分格式与验证见 [协议文档](../../PROTOCOL.md)。

传输层成功，但画面结果不兼容：目标 120×80 青色矩形变成贯穿仪表盘的规则竖向错位带。

结论：公开 Rev-C 5/8 英寸实现的 `address = row × 1568 + x` 记录格式不能直接用于该 6.5 英寸 ROM 91。
这不是屏幕或固件损坏；测试后已用验证过的全帧路径恢复完整仪表盘。

安全措施：

- `DisplayController.update_frame()` 默认抛出 `AuthorizationRequired`；
- CLI 和 GUI 不暴露局部更新；
- 原厂 `0xCC` 调用链现已确认是完整帧比较后的压缩差分流，不是矩形行记录；
- 新编码器已与原厂内存输出核对，但在另行明确授权前不做真机写入。
